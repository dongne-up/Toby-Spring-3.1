# 1장 오브젝트와 의존관계

코드를 리펙토리 할때 가장 먼저 할 일은 커넥션을 가져오는 중복된 코드를 분리하는 것

---

### DB 연결 순서
1. DB 연결을 위한 커넥션을 어떻게 가져올지
2. 사용자 등록을 위해 DB에 보낼 SQL 문장을 담을 statement를 만들고 실행하는 것
3. 작업이 끝나면 사용한 리소스인 statement와 connection 오브젝트를 닫아줘서 소중한 공유 리소스를 시스템에 돌려주기

connection -> statement -> resultset

---

### Statement와 PreparedStatement 개념과 차이

**Statement**
- SQL 문장을 실행하려면 그 문장을 담을 그릇이라고 보면 됨
- 사용자가 입력한 값을 문자로 그냥 이어 붙이기만 함
- 단점: 사용자가 SQL 문법에 쓰이는 특수문자를 일부러 넣으면 SQL 문장의 의미 자체가 바뀔 수 있음 → **SQL 인젝션**

**PreparedStatement**
- Statement의 업그레이드 버전
- ? 자리에 들어가는 값을  SQL 문법으로 해석하지 않게 함
- 아무리 이상한 문자를 넣어도 SQL 문장의 의미가 바뀌지 않음

---

### 디자인 패턴이란?
- 소프트웨어 설계 시 특정 상황에서 자주 만나는 문제를 해결하기 위해 사용할 수 있는 재사용 가능한 솔루션
- 설계 전략이기도 하지만, 굉장히 편리한 커뮤니케이션 수단이기도 함
- 스프링 개발자라면 반드시 알아야 함

---

### 템플릿 메소드 패턴
- 부모가 전체 흐름(뼈대)을 만들어두고 그 안의 일부 세부 동작만 자식이 채우게 하는 디자인 방법
- 상속을 통해 슈퍼클래스의 기능을 확장할 때 사용하는 가장 대표적인 방법
- 변하지 않는 기능은 슈퍼클래스에 만들어두고 자주 변경되며 확장될 기능은 서브클래스에서 만듦
- 서브클래스에서 선택적으로 오버라이드할 수 있도록 만들어둔 메소드를 **훅 메소드**라고 함


**템플릿 메소드 패턴과 훅 메소드는 같은 건가?**
- 템플릿 메소드 패턴은 부모가 전체 흐름을 만들어놓고 그중 일부만 자식이 채워 넣게 하는 디자인 방법 그 자체
- 훅 메소드는 그 안에 나오는 부품 이름 중 하나

- 템플릿 메소드 패턴 (전체 디자인)
  - 추상메소드(필수로 채워야함)
  - 훅 메소드(선택적으로 채울수 있음)
 
---

### 팩토리 메소드 패턴
- 자식 클래스가 어떤 객체를 만들지 결정하게 되는 패턴

---

### 중요하게 알아야할것 - 커넥션 중복 코드 분리
- 커넥션을 가져오는 중복된 코드를 분리하는 것
- 관심사항을 나눠서 담아야 함
- 상속 구조를 통해 성격이 다른 관심사항을 분리한 코드를 만들어내고, 서로 영향을 덜 받도록 했는지 이해하는 것
