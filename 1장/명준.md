## 단어 정리

SI 업체: System Intergration으로 외주 개발 업체를 의미한다

TDD 교육: Test-Deriven Development 테스트 주도 개발을 의미한다

JCO 컨퍼런스: 한국자바개발자협회

유비쿼터스: 언제 어디서나 동시에 존재한다는 것을 의미한다

토비의 스프링 3.1의 1권은 원리와 이해에 대해 다루었고, 2권은 기술과 활용 전략에 대해서 다루었다.

JDBC: 자바 프로그램이 다양한 종류의 데이터베이스에 접속하여 데이터를 읽거나 저장, 수정할 수 있도록 해주는 자바 표준 API를 의미한다.

J2SE: Java 2 Platform Standard Edition으로 데스크톱 및 일반 PC용 응용 프로그램을 개발하기 위한 자바 플랫폼 표준을 의미한다.

XML: eXtensible Markup Language으로 컴퓨터와 사용자가 모두 이해하기 쉽게 데이터를 구조화하고 교환하기 위한 마크업 언어이다. (HTML과의 차이: HTML은 화면에 데이터를 어떻게 보여줄지에 집중한다면, XML은 데이터를 무엇인지 구조화하고 서로 다른 시스템 간에 데이터를 전송하는데 집중한다.)

DispatcherServlet: 스프링 MVC의 핵심 요소로, 클라이언트의 모든 HTTP 요청을 가장 먼저 받아 적합한 컨트롤러(핸들러)에 위임하고 결과를 응답하는 프론트 컨트롤러를 의미한다.

MVC: Model, View, Controller의 약자로, 소프트웨어를 설계할 때 화면과 데이터를 분리하여 관리하는 소프트웨어 디자인 패턴을 의미한다.

AOP: Aspect-Oriented Programming 관점 지향 프로그래밍으로, 애플리케이션의 핵심 비지니스 로직과 공통 부가 기능(로깅, 트랜잭션, 보안 등)을 분리하여 모듈화하는 프로그래밍 패러다임을 의미한다.

가비지컬렉션(GC): 프로그램이 더 이상 사용하지 않는 메모리를 자동으로 찾아서 회수해주는 기능을 의미한다.

서블릿: 클라이언트의 HTTP 요청을 받아서 처리하고, 응답을 만들어 돌려주는 자바 클래스를 의미한다.

## 책 내용 정리

## 1.1 초난감 DAO

**사용자 정보를 JDBC API를 통해 DB에 저장하고 조회할 수 있는 간단한 DAO를 하나 만들어보자**

DAO란?  Data Access Object (데이터 접근 객체)로 DB에 접근하는 코드를 한 곳에 모아둔 객체를 말한다

### 1.1.1 User

Id, Name, Password 컬럼으로 이루어진 데이터 타입의 기본적인 변수들을 선언하고 set, get 함수를 만들었다.

### 1.1.2 UserDao

### 1. DB 연결을 위한 Connection을 가져온다

```java
Class.forName("com.mysql.jdbc.Driver");
Connection c = DriverManager.getConnection(
        "jdbc:mysql://localhost/springbook", "root", "zxcv8240?");
```

### 2. SQL을 담은 Statement(또는 PreparedStatement)를 만든다

```java
PreparedStatement ps = c.prepareStatement(
        "select * from users where id = ?");
ps.setString(1, id);
```

### 3. 만들어진 Statement를 실행한다

```java
ResultSet rs= ps.executeQuery();
```

### 4. 조회의 경우 SQL 쿼리의 실행 결과를 ResultSet으로 받아서 정보를 저장할 오브젝트(User)에 옮겨준다

```java
rs.next();
User user = new User();
user.setId(rs.getString("id"));
user.setName(rs.getString("name"));
user.setPassword(rs.getString("password"));
```

### 5. 작업 중에 생성된 Connection, Statement, ResultSet 같은 리소스는 작업을 마친 후 반드시 닫아준다

```java
rs.close();
ps.close();
c.close();
```

### 6. JDBC API가 만들어내는 예외를 잡아서 직접 처리하거나, 메소드에 throws를 선언해서 예외가 발생하면 메소드 밖으로 던지게 한다

이 메소드 전체를 감싸는 선언부에 있음

```java
public User get(String id) throws ClassNotFoundException, SQLException {
    // 위 1~5번 코드 전부
}
```

### 1.1.3 main()을 이용한 DAO 테스트 코드

```java
public static voidmain(String[] args) throwsClassNotFoundException, SQLException {
    UserDao dao = newUserDao();
```

## 1.2 DAO의 분리

### 1.2.1 관심사의 분리

우린 미래를 지키기 위해 확장성에 대해서 고려하는 개발자가 되어야 한다. Y2K를 생각해보아도…

따라서 관심사의 분리는 중요하다. DAO를 수백개 수정할 순 없잖냐. 변화는 하나지만 이걸 고치기 위한 코스트를 줄이기 위해 관심사를 분리하자.

### 1.2.2 커넥션 만들기의 추출

getConnection()메소드를 따로 만들어, DB연결 코드를 독립적인 코드로 만들어주어 재사용성을 높인다.

**뭐가 좋은가?** → DB연결의 부분이 바뀌었을 경우(종류나 접속 방법)에 한 곳만 수정하면 되니까 관심이 집중/정확 해진다. (리팩토링이다.)

### 1.2.3 DB 커넥션 만들기의 독립

우리의 코드가 아주 대단한 사용자 관리 시스템이 되었다고 치자. 그런 뒤 N사와 D사에게 이 서비스를 돈을 받고 제공해주기로 했다. 그런데.. 문제는 N사와 D사가 각각 다른 DB를 쓴다는 것이다. 이걸 어떻게 해결 할 것인가? 아예 UserDao 소스 코드를 주면 되지만 그냥 바이너리 파일 정도로만 주고 싶고. 우리의 엄청난 코드는 숨기고 싶다. **어떻게 해결 할 것인가?** → 분리.

상속을 통해 분리해보자.

UserDao와 getConnection의 메소드를 추상 메소드로 수정하고 N사와 D사에서 UserDao를 상속받아 사용하게 하는 것이다! 이제 UserDao의 코드 수정없이 두 개의 관심이 분리되면서 문제를 해결한 듯 보인다. 하지만 상속을 사용했다는 것은, 다중 상속이 허용되지 않는 JAVA에서는 다른 용도의 상속기능을 추가할 수가 없다. 다른 DAO 클래스에 커넥션 생성하는 코드를 적용할 수 없다는 것도 한 몫 한다.

## 1.3 DAO의 확장

### 1.3.1 클래스의 분리

DB 커넥션 기능을 분리시킨 SimpleConnectionMaker  클래스를 제작하여 사용하자.

하지만 아직 N사에서 다른 DB를 쓰려고 하면 UserDao를 수정해야한다.

### 1.3.2 인터페이스의 도입

서로 긴밀하게 연결되어 있지 않도록 중간에 추상적인 느슨한 연결고리를 만들어 주는 것이 핵심이다. 따라서 인터페이스를 사용하여 어떤 일을 하겠다는 기능만 정의해 놓는 것이다. 어떻게 하겠다는 X.

```java
package springbook.user.dao;
...
public interface ConnectionMaker {
    public Connection makeConnection() throws ClassNotFoundException,
            SQLException;
}
```

자신들의 DB 연결 기술을 이용해 DB 커넥션을 가져오도록 메서드를 작성해주면 된다.

```java
connectionMaker = new DConnectionMaker();
```

하지만 이런 초기의 코드가 UserDao에 남아있다.
