## 0단계

```java
public class UserDao {
    private DataSource dataSource;
    public void setDataSource(DataSource dataSource) { this.dataSource = dataSource; }

    public void add(User user) throws SQLException {
        Connection c = null;  //데베 연결
        PreparedStatement ps = null;  //데베에 SQL문 보낼 명령서
        try {
            c = dataSource.getConnection();
            ps = c.prepareStatement("insert into users(id, name) values(?, ?)");
            ps.setString(1, user.getId());
            ps.setString(2, user.getName());
            ps.executeUpdate();
        } catch (SQLException e) {
            throw e;
        } finally {
            if (ps != null) { try { ps.close(); } catch (SQLException e) {} }
            if (c != null)  { try { c.close();  } catch (SQLException e) {} }
        }
    }
}
```

문제점이 있는가?

⇒ try/catch/finally의 반복 문제점이 존재한다. 이 이야기가 3장의 시작이다.

## 1단계

```java
// Strategy 인터페이스
public interface StatementStrategy {
    PreparedStatement makePreparedStatement(Connection c) throws SQLException;
}

// ConcreteStrategy
public class AddStatement implements StatementStrategy {
    private User user;
    public AddStatement(User user) { this.user = user; }
    public PreparedStatement makePreparedStatement(Connection c) throws SQLException {
        PreparedStatement ps = c.prepareStatement("insert into users(id, name) values(?, ?)");
        ps.setString(1, user.getId());
        ps.setString(2, user.getName());
        return ps;
    }
}
```

바뀌는 않는 부분(커넥션 관리)과 바뀌는 부분(SQL)을 인터페이스로 쪼갠다.

```java
// Context
public class UserDao {
    private DataSource dataSource;
    public void setDataSource(DataSource dataSource) { this.dataSource = dataSource; }

    public void jdbcContextWithStatementStrategy(StatementStrategy stmt) throws SQLException {
        Connection c = null;
        PreparedStatement ps = null;
        try {
            c = dataSource.getConnection();
            ps = stmt.makePreparedStatement(c);
            ps.executeUpdate();
        } finally {
            if (ps != null) { try { ps.close(); } catch (SQLException e) {} }
            if (c != null)  { try { c.close();  } catch (SQLException e) {} }
        }
    }

    public void add(User user) throws SQLException {
        StatementStrategy st = new AddStatement(user);
        jdbcContextWithStatementStrategy(st);
    }
}
```

## 3단계

```java
public class JdbcContext {
    private DataSource dataSource;
    public void setDataSource(DataSource dataSource) { this.dataSource = dataSource; }

    public void workWithStatementStrategy(StatementStrategy stmt) throws SQLException {
        Connection c = null;
        PreparedStatement ps = null;
        try {
            c = dataSource.getConnection();
            ps = stmt.makePreparedStatement(c);
            ps.executeUpdate();
        } finally {
            if (ps != null) { try { ps.close(); } catch (SQLException e) {} }
            if (c != null)  { try { c.close();  } catch (SQLException e) {} }
        }
    }
}
```

```java
public class UserDao {
    private JdbcContext jdbcContext;
    public void setJdbcContext(JdbcContext jdbcContext) { this.jdbcContext = jdbcContext; }

    public void add(final User user) throws SQLException {
        jdbcContext.workWithStatementStrategy(
            new StatementStrategy() {

                    ps.setString(1, user.getId());
                    ps.setString(2, user.getName());
                    return ps;
                }
            }
        );
    }
}
```

#### 왜 이제는 빈 등록이 필요한가

JdbcContext는 이제 UserDao뿐 아니라 다른 DAO(BoardDao 등)에서도 공유될 수 있는 독립된 오브젝트가 됐다. 그리고 dataSource라는 외부 의존 오브젝트를 필요로 한다. 이런 조건(공유됨 + 외부 의존성 있음)을 만족하면 스프링 빈으로 등록해서 컨테이너가 생성과 조립을 대신하게 만드는 게 맞다.

```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans
           http://www.springframework.org/schema/beans/spring-beans-3.1.xsd">

    <bean id="dataSource" class="org.springframework.jdbc.datasource.SimpleDriverDataSource">
        <property name="driverClass" value="com.mysql.jdbc.Driver" />
        <property name="url" value="jdbc:mysql://localhost/testdb" />
        <property name="username" value="spring" />
        <property name="password" value="book" />
    </bean>

    <bean id="jdbcContext" class="springbook.dao.JdbcContext">
        <property name="dataSource" ref="dataSource" />
    </bean>

    <bean id="userDao" class="springbook.dao.UserDao">
        <property name="jdbcContext" ref="jdbcContext" />
    </bean>

</beans>
```

- JdbcContext.workWithStatementStrategy() = **템플릿** (고정된 흐름)
- new StatementStrategy() { ... } = **콜백** (매번 새로 만들어 한 번 쓰고 버림)
- jdbcContext.workWithStatementStrategy(콜백) 호출 그 순간 = **템플릿 호출과 동시에 콜백이 DI 되는 지점**

## 제네릭 리턴 타입 확장

```java
public interface StatementStrategy<T> {
    T doInStatement(Connection c, PreparedStatement ps) throws SQLException;
}

public <T> T jdbcContextWithStatementStrategy(String sql, StatementStrategy<T> stmt) throws SQLException {
    Connection c = null;
    PreparedStatement ps = null;
    try {
        c = dataSource.getConnection();
        ps = c.prepareStatement(sql);
        return stmt.doInStatement(c, ps);
    } finally {
        if (ps != null) { try { ps.close(); } catch (SQLException e) {} }
        if (c != null)  { try { c.close();  } catch (SQLException e) {} }
    }
}
```
